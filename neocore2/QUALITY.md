# Quality & Stability Rules (NewEngine)

Этот документ фиксирует обязательные правила кодовой базы для уровня стабильности, приемлемого для больших проектов (
ориентир: AAA).

## 1) Panic policy

### Разрешено

- `panic!` / `expect` только для **невозможных состояний**, которые означают баг разработчика и нарушение контракта (
  debug-only инварианты, ABI контрактные нарушения, внутренняя несовместимость типов).

### Запрещено

- Паники из-за пользовательских данных: конфиги, ассеты, входные файлы, сетевые ответы.
- Паники из-за отсутствующих scratch ресурсов в ECS.

## 2) Errors are values

- Всё, что может отказать в рантайме, должно возвращать `Result` и/или деградировать функционально.
- Редактор не должен падать из‑за отсутствия необязательных сервисов: либо выключать фичу, либо показывать объяснение.

## 3) Determinism

- Порядок итерации по сущностям, когда это влияет на результат, должен быть **явно стабилен**:
    - сортировка по `EntityId::stable_u64()` (или эквивалентной стабильной проекции ключа).
- `World::tick` задаётся внешне (frame index/fixed tick) и используется для change tracking.

## 4) Derived state ownership

Derived state обновляется строго в одном месте:

- Transform derived (`GlobalTransform`, `WorldPose`) — `newengine-transform`.
- Bounds derived (`Bounds.world_*`) и union кеш (`SceneBounds`) — `newengine-scene` (runtime feature).

Контроллеры/UI/рендер не должны «допиливать» derived state по месту.

## 5) Crate responsibilities

У каждого крейта должен быть README с:

- что крейт **делает**
- что крейт **не делает**
- основные инварианты и контракты

## 6) Host vs Plugin boundary

- `newengine-plugin-api` — чистый ABI контракт. Он не знает про конкретные реализации плагинов.
- Plugin-owned сервисы регистрируются через HostApi и диагностируются через список сервисов.
