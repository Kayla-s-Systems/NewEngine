# NorthStar Refactor Wave 2 — 2026-07-12

## NEF8 asset format crate

`newengine-asset-format-nef8/src/lib.rs` was a genuine registry monolith: descriptor policy, 24 format namespaces, registry construction, lookup and tests occupied 853 lines. Binary YDD decoding added another 478-line file.

The public API is preserved while ownership is now separated:

```text
newengine-asset-format-nef8/src/
├── lib.rs                  # 43 lines; compatibility facade
├── descriptor.rs           # 130 lines; descriptor/write-back policy
├── formats.rs              # 415 lines; 24 data-only format namespaces
├── registry.rs             # 89 lines; static macro-driven table + lookup
├── tests.rs                # 46 lines; registry contracts
├── ydd_binary.rs           # 19 lines; compatibility facade
└── ydd_binary/
    ├── types.rs            # 116 lines
    ├── decode.rs           # 267 lines
    └── tests.rs            # 94 lines
```

The 24 repetitive `Nef8FormatSpec` initializers are now generated by two local macros (`listfile_spec!` and `package_spec!`). Write-back policy is evaluated once per descriptor instead of repeating the same extension match four times. Extension lookup normalizes the caller input once and compares directly with static normalized extensions.

## Render instance upload

The forward pass previously issued one `write_buffer` call per instance batch. Shadow extraction did the same. The observed Forest Road frame contained 26 forward batches and 13 shadow batches. These are now packed into one contiguous upload per pass:

- Forward: 26 batches, 31 instances, 5,952 bytes, 1 write.
- Shadow: 13 batches, 15 instances, 2,880 bytes, 1 write.
- Observed write-call reduction: 39 → 2 (94.9%).
- CPU flattening storage is retained and reused after the first peak frame.

## Additional modularization

The 1,048-line sky bridge was separated into type, sampling, runtime and lighting modules while preserving the original sky facade and runtime behavior. Repeated little-endian binary cursor logic in UI/render protocols was consolidated behind one bounded reader implementation, including length limits and contextual truncation errors.
