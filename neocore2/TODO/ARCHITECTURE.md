# 🧭 NewEngine — Архитектурная Доктрина

## Референс для зачистки Legacy

---

# 1️⃣ Engine as Host. Service as Plugin.

## Принцип

Ядро — оркестратор жизненного цикла.
Вся функциональность — плагины.

## Требования

* Core не знает конкретных типов сервисов
* Нет прямых зависимостей core → конкретный модуль
* Взаимодействие только через контракт

## Признаки Legacy

* `use crate::specific_module`
* enum с перечислением плагинов
* match по конкретным plugin id
* знание структуры конкретного сервиса

## Архитектурный инвариант

Core должен компилироваться без любых конкретных плагинов.

---

# 2️⃣ ABI — это закон

## Принцип

`newengine-plugin-api` — чистый контракт.
Никаких реализаций. Никакой конкретики.

## В ABI допустимо

* PluginId
* PluginKind
* Version
* CapabilityDesc[]
* Экспортируемые точки входа

## В ABI запрещено

* Типы ассетов
* Структуры сервисов
* Жёсткие enum плагинов
* Match по типам

## Нарушение

Если ABI знает про AssetManager / Renderer / Importer — это ошибка архитектуры.

---

# 3️⃣ Capability-Driven Архитектура

## Принцип

Зависимость от capability, а не от plugin id.

❌ Неправильно:

```rust
if plugin.id == "newengine.assets"
```

✅ Правильно:

```rust
if plugin.capabilities.contains("asset.registry.v1")
```

## Цель

* Расширяемость
* Множественные реализации
* Замена без переписывания ядра

## Legacy

* Жёсткие строки ID
* Хардкод имён DLL
* Логика по конкретному имени

---

# 4️⃣ Конфиг — источник истины

## Принцип

Поведение задаётся конфигом или capability.

## Legacy-примеры

* Жёсткие пути к shader
* Захардкоженные папки assets
* Вшитые расширения файлов

## Правильная модель

* Явная регистрация VFS source
* Importer объявляет поддерживаемые форматы
* Shader pipeline не знает структуру файловой системы

---

# 5️⃣ Determinism First

## Принцип

Поведение не зависит от:

* Порядка HashMap
* Порядка загрузки DLL
* ОС
* Случайных ID

## Требования

* Deterministic контейнеры
* Сортировка перед регистрацией
* Фиксированный порядок инициализации

## Legacy

* FxHashMap
* Итерация без сортировки
* Нестабильный порядок capability

---

# 6️⃣ Явная регистрация всего

## Принцип

Никакой магии.

Если источник существует — он зарегистрирован.

## Должно быть

* VfsSourceRegistry
* SourceKind
* Приоритет слоя

## Проверка

* Можно вывести список всех источников
* Можно изменить приоритет
* Можно отключить источник

Если нет — это legacy.

---

# 7️⃣ Изоляция слоёв

## Core не знает

* Render API
* ECS storage
* Asset layout
* UI детали

## Controllers

* Не знают рендер
* Не лезут в storage напрямую

## Render

* Не знает input
* Не знает gameplay

---

# 8️⃣ Replace by Abstraction

Любой компонент должен быть заменяемым:

* Renderer → Vulkan / DX / Software
* AssetSource → Pak / FS / Network
* Importer → GLTF / FBX / OBJ

Если нельзя заменить — есть жёсткая сцепка.

---

# 9️⃣ Fail-Fast и Диагностика

## Принцип

Ошибки не должны быть тихими.

## Требования

* Контекстные ошибки
* Структурированный лог
* Запрет silent fallback

## Legacy

* unwrap()
* expect без контекста
* swallow error

---

# 🔟 Минимальное ядро

Core содержит только:

* Plugin Manager
* Service Registry
* Lifecycle
* Startup Config
* Host API

Если в core есть:

* Логика ассетов
* Логика сцены
* Логика шейдеров
* Логика камеры

→ архитектурное разрастание.

---

# 1️⃣1️⃣ Контракты важнее удобства

❌ Быстро, но неправильно:

```rust
use crate::asset_manager::AssetManager;
```

✅ Архитектурно правильно:

```rust
let registry = host.require_capability("asset.registry.v1") ?;
```

Мы жертвуем краткосрочным удобством ради долгосрочной масштабируемости.

---

# 1️⃣2️⃣ Расширяемость важнее текущей задачи

Перед добавлением фичи задаётся вопрос:

> Это решение масштабируется?

Если нет — решение не принимается.

# 1️⃣3️⃣ Единый источник математики — newengine-math

## Принцип

Вся математика в экосистеме NewEngine должна использоваться
исключительно из `newengine-math`.

Это единственный допустимый источник:

* Векторов
* Кватернионов
* Матриц
* Трансформаций
* Геометрии
* Deterministic контейнеров

---

## Запрещено

* Использование `glam`
* Использование `nalgebra`
* Использование внешних math-библиотек
* Локальные math-реализации в модулях
* Разные типы Vec3 в разных crate

---

## Почему это критично

### 1. Детерминизм

Одна реализация → одинаковое поведение на всех платформах.

### 2. ABI-стабильность

Типы должны быть едиными во всей экосистеме.

### 3. Отсутствие скрытых конверсий

Никаких `.into()` между разными Vec3.

### 4. Централизованная эволюция

Оптимизация, SIMD, фиксированная точность — делаются в одном месте.

---

## Архитектурный инвариант

Ни один crate NewEngine не имеет права вводить собственные math-типы.

Если модулю не хватает функционала — он расширяет `newengine-math`,
а не добавляет зависимость.

---

## Legacy-признаки

* `use glam::Vec3`
* `type Vec3 = ...` внутри crate
* Внутренние копии матриц
* Вспомогательные math-utils вне newengine-math

Обнаружение таких случаев — обязательная зачистка.

# 1️⃣4️⃣ Запрет глобального состояния

Запрещено:

* static mut
* Глобальные singleton
* Скрытые registries

Всё живёт в контексте Host.

---

# 1️⃣4️⃣ Минимум связности

Норма:

* Зависимости через trait

* Host-mediated доступ

Связность — главный враг AAA-архитектуры.

---

# 1️⃣5️⃣ Протокол зачистки Legacy

При обнаружении legacy:

1. Определить нарушенный принцип
2. Изолировать зависимость
3. Вынести контракт
4. Убрать знание о конкретике
5. Проверить заменяемость
6. Проверить детерминизм

---

# 🧱 Критерий AAA-готовности

Система считается архитектурно чистой если:

* Core собирается без конкретных плагинов
* Любой плагин можно заменить
* Любой source можно отключить
* Нет match по ID
* Нет хардкода путей
* Всё capability-driven
* Контракты стабильны

# 1️⃣6️⃣ Деградация вместо смерти

## Принцип

Отсутствие функционала — это предупреждение и управляемая деградация,
но не краш и не остановка Engine.

Система должна быть отказоустойчивой по слоям.

## Правило

Если capability отсутствует:

* Логируем предупреждение
* Включаем fallback-режим
* Ограничиваем функциональность
* Продолжаем работу

Но:

* Не паникуем
* Не abort
* Не валим весь Engine

## Примеры корректной деградации

### Нет Renderer

→ Engine запускается в headless-режиме.

### Нет Asset Importer

→ Загрузка новых форматов недоступна, но runtime продолжает работать.

### Нет Network Source

→ Используются только локальные VFS-источники.

### Нет Editor Plugin

→ Engine работает как runtime.

---

## Запрещённая модель

❌ Отсутствие одного плагина валит всё ядро.
❌ Host жёстко требует конкретный plugin id.
❌ panic! из-за отсутствия необязательной capability.

---

## Градация критичности

### Critical capability

Без неё невозможен жизненный цикл.
→ Engine не стартует.

### Required at runtime

Функциональность отключается, но Engine живёт.

### Optional

Просто предупреждение.

Host обязан различать эти уровни.

---

## Архитектурный инвариант

Engine должен быть живучим.

Плагин — расширение.
Ядро — стабильная основа.

Если плагин падает — Host изолирует его.
Если capability отсутствует — система деградирует.
Если слой недоступен — используются нижележащие слои.

---

# 🧩 Финальная формула

> NewEngine — это Host с контрактом.
> Всё остальное — плагины.
> Плагины определяются capability.
> Поведение задаётся конфигом.
> Детерминизм обязателен.
> Хардкод — враг.
